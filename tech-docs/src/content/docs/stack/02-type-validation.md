| 項目 | 選定 | 備考 |
|------|------|------|
| API型共有 | Hono RPC | コード生成なし |
| 共通型/バリデーション | zod | packages/shared に配置 |
| 環境変数 | zod + 自前 | 起動時バリデーション |

## Hono RPC

HonoのRPC機能でフロントエンドとAPIの型を共有。

**選定理由**
- コード生成不要
- エンドツーエンドの型安全

**検討した代替案**

| 技術 | 不採用理由 |
|------|-----------|
| OpenAPI + コード生成 | ビルドステップが増える |
| GraphQL | 小〜中規模には過剰 |

## zod

TypeScriptファーストのスキーマバリデーション。

**選定理由**
- 型推論が強力
- エコシステムが充実（react-hook-form, Hono等）
- 軽量

**用途**
- APIリクエスト/レスポンスのバリデーション
- フォームバリデーション
- 環境変数の検証
- URLパラメータの型付け
