## 設計指針

### Simple vs Easy

「Easy（簡単）」ではなく「Simple（単純）」を選ぶ。

| Simple | Easy |
|--------|------|
| 概念が少ない | 便利な機能が多い |
| 依存が少ない | 抽象化が厚い |
| 理解しやすい | 学習コストが低い（最初だけ） |
| デバッグしやすい | 魔法が多い |

### 原則

1. **必要になったら足す**: 最初から入れない。辛くなったら足す
2. **Web標準に寄せる**: 独自APIより標準API
3. **依存を減らす**: ライブラリは厳選
4. **IFに対してテスト**: 実装詳細ではなく公開インターフェースをテスト
5. **外部IOは型で守る**: URLパラメータ、APIレスポンス等はzodでバリデーション
