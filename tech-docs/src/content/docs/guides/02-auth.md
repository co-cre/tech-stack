| | Cloudflare Access | Firebase Auth | Lucia | 自前JWT |
|--|-------------------|---------------|-------|---------|
| 向いてる | 社内ツール | 一般向けSaaS | 自由度重視 | 完全制御 |
| 実装コスト | 低 | 低 | 中 | 高 |
| 依存 | CF | Firebase | なし | なし |

## Cloudflare Access

Cloudflareのゼロトラストアクセス管理。

### 選定理由

- 実装不要（設定のみ）
- IdP連携（Google、GitHub等）
- ワーカー前段で認証

### 向いているケース

- 社内ツール
- 管理画面
- 限定ユーザー

### 向いていないケース

- 一般公開アプリ
- カスタムUI必須
- ユーザー登録フロー

## Firebase Auth

Firebaseの認証サービス。

### 選定理由

- 実装が簡単
- 多様な認証方法（Email、SNS、電話）
- SDK充実

### 向いているケース

- 一般向けSaaS
- モバイルアプリ
- 素早くリリースしたい

### 向いていないケース

- Firebase依存を避けたい
- 完全カスタムの認証フロー
- Cloudflareで完結したい

## Lucia

軽量な認証ライブラリ。

### 選定理由

- フレームワーク非依存
- セッション管理が柔軟
- 依存が少ない

### 向いているケース

- カスタム認証フロー
- 自前DB管理したい
- ベンダーロックイン回避

### 向いていないケース

- 最速でリリースしたい
- チームに認証知識がない

## 自前JWT

完全に自前実装。

### 選定理由

- 完全な制御
- 外部依存なし

### 向いているケース

- 特殊な要件
- セキュリティ専門家がいる

### 向いていないケース

- ほとんどのケース（避けるべき）
- チームにセキュリティ専門家がいない

## 選定フローチャート

```
社内ツール？
├── Yes → Cloudflare Access
└── No
    └── Firebase使ってる or 素早くリリース？
        ├── Yes → Firebase Auth
        └── No
            └── カスタム認証フロー必要？
                ├── Yes → Lucia
                └── No → Firebase Auth
```

## 注意点

- 自前JWTは最後の手段
- セキュリティは既存ソリューションに任せる
- 認証は「作らない」のが正解
