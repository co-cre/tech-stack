「Easy（簡単）」ではなく「Simple（単純）」を選ぶ。

## Simple vs Easy

| Simple | Easy |
|--------|------|
| 概念が少ない | 便利な機能が多い |
| 依存が少ない | 抽象化が厚い |
| 理解しやすい | 学習コストが低い（最初だけ） |
| デバッグしやすい | 魔法が多い |

## なぜSimpleを選ぶのか

**Easyの罠**
- 最初は楽だが、時間とともに複雑化
- 抽象化の裏を理解しないとデバッグ困難
- バージョンアップで挙動が変わるリスク

**Simpleのメリット**
- 長期的に保守しやすい
- 新メンバーが理解しやすい
- トラブル時に原因特定が容易

## 具体例

| カテゴリ | Simple | Easy |
|----------|--------|------|
| ORM | Drizzle（SQLに近い） | Prisma（独自クエリ言語） |
| API | Hono（Web標準） | NestJS（デコレータ多用） |
| 状態管理 | useState + React Query | Redux |
| CSS | Tailwind | CSS-in-JS（runtime） |

## 判断基準

新しい技術を導入する際のチェックリスト:

1. **学習コスト**: 中身を理解するのにどれくらいかかるか
2. **依存の深さ**: 抽象化レイヤーは何層か
3. **デバッグ容易性**: エラー時にスタックトレースを追えるか
4. **逃げ道**: 別の選択肢に移行できるか
