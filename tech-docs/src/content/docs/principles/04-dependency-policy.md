## 原則

**依存は少なく、厳選する。**

## 導入前チェックリスト

新しいライブラリを追加する前に確認:

1. **本当に必要か**: 自前実装で十分ではないか
2. **メンテナンス状況**: 最終更新日、Issue対応速度
3. **バンドルサイズ**: [bundlephobia](https://bundlephobia.com/)で確認
4. **依存の深さ**: node_modulesがどれだけ増えるか
5. **代替手段**: Web標準APIで代替できないか

## ライブラリの分類

| 分類 | 例 | 姿勢 |
|------|-----|------|
| コア | React, Hono, Drizzle | 慎重に選定、長期利用 |
| ユーティリティ | date-fns, zod | 必要なら導入 |
| UI | shadcn/ui | コピー方式を優先 |
| 一時利用 | マイグレーションツール等 | devDependencies |

## Web標準を優先

| やりたいこと | ライブラリ不要 |
|-------------|---------------|
| HTTP通信 | fetch API |
| 日時取得 | Date, Intl.DateTimeFormat |
| UUID生成 | crypto.randomUUID() |
| URLパース | URL, URLSearchParams |
| フォームデータ | FormData |

## 依存の更新

- **定期的にアップデート**: 溜めると辛い
- **破壊的変更の追従**: CHANGELOGを読む
- **ロックファイルをコミット**: bun.lockb

## 削除の判断

以下に該当したら削除を検討:

- 使用箇所が1-2箇所
- より良い代替手段が出た
- メンテナンスが止まった
- セキュリティ脆弱性が放置されている
